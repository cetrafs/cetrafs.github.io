Many hosts, one LUN.
One filesystem.

cetrafs is a clustered, shared-disk filesystem for Linux. Several hypervisors mount the same iSCSI or Fibre Channel LUN at once and keep their VM disk images directly on it, coordinating through the storage itself. It is an open alternative to VMFS.

Shared-disk clustering

Up to 64 nodes mount one block device. Each node allocates only from the Zone Groups it owns, so two nodes never draw from the same free-space pool.

One atomic primitive

Every contested claim is a single SCSI COMPARE AND WRITE on one 512-byte record. It is the same idea as VMFS's ATS, with no DLM, no corosync and no network protocol in the data path.

Crash consistent

Each node has its own write-ahead redo journal. It is replayed at mount and whenever a dead peer is reclaimed, and a replay guard refuses to roll back blocks that someone else has since rewritten.

Checksummed end to end

CRC32C on every on-disk structure, verified by the kernel on read, with a retry for torn reads. Per-inode generations catch inode-number reuse across nodes.

Live migration

With nofilelock, a VM image can be open on two nodes during a Proxmox/qemu online-migration handoff, and the handoff stays coherent even across a snapshot.

Self-healing upkeep

Online defragmentation, a background scrubber that reclaims leaked blocks, and an fsck.cetra that repairs faults with one correct answer and refuses to guess at the rest.

Built for one workload

cetrafs is a VM datastore, not a general-purpose POSIX cluster filesystem. Keeping to that narrow contract is what lets it run without a cluster lock manager in the I/O path.

Young software. Honest about it.

cetrafs has been reviewed, fuzzed and crash-tested heavily, but it is pre-1.0 and has not had years of production use the way VMFS and ext4 have. Try it on storage you can afford to reformat, and keep independent backups.
